# Workflow Rules

- Always plan before coding. Create a clear outline of the steps needed to complete the task.
- Write clean and maintainable code. Follow the project's coding standards and best practices.
- Use comments to explain complex logic, but avoid over-commenting. The code should be self-explanatory where possible.
- Test your code thoroughly. Write unit tests for critical functions and ensure all tests pass before merging
- Update documentation as needed. If your changes affect the user-facing API or functionality, make sure to update the relevant documentation. Use README.md for high-level documentation and inline comments for code-specific explanations. If needed, create a docs/ directory for more detailed documentation.
